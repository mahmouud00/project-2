# التصميم المعماري — MYTech Solutions (Backend)

> الحالة: **متنفّذ** (الإصدار 0.1.0). الأقسام تحت هي التصميم الأصلي. التغييرات اللي حصلت وقت التنفيذ:
> - **المكتبة بتتألف من جوه السيستم** بدل استيراد ملف الإكسيل (قرار صاحب المشروع): شوف `docs/LIBRARY.md`.
>   تعريف النموذج (المتغيرات، المعادلات، القطع لكل خامة، الزجاج، الإكسسوار، التحقق، الرسمة) متخزن كمستند JSON واحد في `product_models.definition`،
>   والنشر بيعمل `formula_set_versions` مجمّدة فيها السيستم كله.
> - **دور الـ owner بقى BYPASSRLS** عشان النسخ الاحتياطي والاسترجاع والـ data migrations تشوف كل الشركات. الـ API (`mytech_app`) فاضل مقيّد بالـ RLS.
> - التسعير cost-plus من نتيجة الحساب (أو سعر للمتر) بقوائم أسعار، والتكلفة بتتحسب بالترتيب: سعر الشركة ← سعر اللون ← السعر المرجعي في المكتبة.
> - إعدادات المكنة (سلاح المنشار، أطراف العود، أقل باقي) إعدادات للشركة، مش ثوابت في الكود.
> - الأماكن اللي عليها ⚑ اتحسمت بافتراضات قابلة للتغيير. شوف "قرارات افتراضية" في `docs/PROGRESS.md`.

## 1. الفكرة العامة

كود واحد، بيشتغل في وضعين حسب إعداد واحد `APP_MODE=offline|online`:

```
                ┌──────────────────────── نفس الكود ────────────────────────┐
 الأوفلاين:     │ جهاز سيرفر في المصنع: PostgreSQL + API (Windows Service)   │ ◄── الأجهزة على الشبكة الداخلية
                │ شركة واحدة (company_id موجود برضه)، ترخيص من ملف موقّع      │
                └───────────────────────────────────────────────────────────┘
                ┌───────────────────────────────────────────────────────────┐
 الأونلاين:     │ سيرفر سحابي: PostgreSQL + API خلف Reverse Proxy (HTTPS)     │ ◄── الفروع من الإنترنت
                │ شركات كتير، عزل كامل (RLS)، ترخيص = اشتراك في قاعدة البيانات│
                └───────────────────────────────────────────────────────────┘
```

الفرق بين الوضعين محصور في **3 حاجات بس**، وكلها ورا واجهات (interfaces):
1. **مزود الترخيص** `LicenseProvider`: ملف موقّع (أوفلاين) أو اشتراك في الداتابيز (أونلاين).
2. **مصدر مكتبة القطاعات**: استيراد حزمة موقّعة من ملف (أوفلاين) أو تحديث مركزي (أونلاين). الاتنين بيكتبوا في نفس الجداول.
3. **خدمات التشغيل**: الاكتشاف على الشبكة (أوفلاين بس)، وإجبار HTTPS (أونلاين).

باقي السيستم (المحرك، المبيعات، المخازن…) مايعرفش هو شغال في أنهي وضع.

### اقتراحات تقنية (محتاجة موافقتك قبل ما أغيّر حاجة من المطلوب)

1. **WinSW بدل pywin32 للـ Windows Service.** WinSW برنامج صغير مفتوح المصدر بيشغّل أي برنامج كخدمة: بيبدأ مع الجهاز، وبيعيد التشغيل لو وقع، وبيعمل لوجات بتدوّر. pywin32 بيحتاج كود خدمة خاص وبيعمل مشاكل مع الـ venv. الاتنين بيحققوا "يبدأ أوتوماتيك مع الجهاز".
2. **Python مدمجة (embeddable) + wheels بدل PyInstaller للتغليف على ويندوز.** PyInstaller بيعمل مشاكل مع الأنتي فيروس (false positives) ومع التحديثات الجزئية. النسخة المدمجة بتتحط في فولدر بالإصدار (`C:\MYTech\app\1.2.0\`) وده بيسهّل الرجوع (rollback) جدًا.
3. **PostgreSQL Row-Level Security كخط دفاع تاني** فوق الفلترة في الكود (التفاصيل في §4). ده اللي بيخلي "مستحيل شركة تشوف بيانات شركة تانية" حقيقي حتى لو مبرمج نسي فلتر.
4. **WebSocket للتزامن اللحظي** (مش مذكور صراحةً بس "كل حاجة متزامنة لحظيًا" محتاجاه): الأجهزة بتستقبل "السجل X اتغير" وتعيد تحميله. **ده مش offline sync**؛ مفيش أي تخزين محلي ولا مزامنة بعد انقطاع.

## 4. عزل الشركات (Multi-tenancy)

### القاعدة
كل جدول بيانات فيه `company_id UUID NOT NULL`، حتى في الأوفلاين (شركة واحدة).

### خطين دفاع
1. **في الكود**: كل الاستعلامات بتعدي على `TenantSession` بيضيف `WHERE company_id = :current` أوتوماتيك (SQLAlchemy `with_loader_criteria`)، وبيملا `company_id` في الإدخال. ممنوع الـ endpoint ياخد `company_id` من الطلب نفسه، بييجي من التوكن بس.
2. **في الداتابيز (RLS)**: كل جدول عليه:
   ```sql
   ALTER TABLE x ENABLE ROW LEVEL SECURITY;
   ALTER TABLE x FORCE ROW LEVEL SECURITY;
   CREATE POLICY tenant_isolation ON x
     USING (company_id = current_setting('app.company_id')::uuid)
     WITH CHECK (company_id = current_setting('app.company_id')::uuid);
   ```
   والـ API بيعمل `SET LOCAL app.company_id = '…'` في أول كل transaction. يوزر الداتابيز بتاع الـ API **مش owner للجداول ومش BYPASSRLS**. لو `app.company_id` مش متحدد، الاستعلام بيرجع صفر صفوف (مش كل الصفوف).
   - الـ migrations بتشتغل بيوزر تاني (owner).
   - أداة الـ vendor (إدارة الاشتراكات) بتشتغل بيوزر ليه صلاحية مخصوصة.

### مكتبة القطاعات المشتركة ⚑
المكتبة العامة "مشتركة بين كل العملاء"، والقاعدة بتقول "كل جدول فيه company_id". الحل المقترح: **شركة نظام** ثابتة (`PLATFORM_COMPANY_ID`) هي اللي بتملك صفوف المكتبة. سياسة RLS على جداول المكتبة:
- القراءة: `company_id = current OR company_id = PLATFORM`.
- الكتابة: للشركة نفسها بس على صفوفها؛ صفوف المكتبة بتتكتب من مسار الاستيراد/التحديث بس.

كده القاعدة ماتتكسرش، والمكتبة بتتحدث مرة واحدة للكل في الأونلاين.

### الفروع
`branch_id` على كل حاجة مربوطة بمكان (المخزن، الحركة، الخزينة، أمر الشغل، عرض السعر). صلاحيات المستخدم = (دور × فرع): ممكن يكون "مخازن" في فرع 1 و"مبيعات" في فرع 2. الاستعلامات بتتفلتر كمان بالفروع المسموحة للمستخدم (في الكود؛ الفروع داخل نفس الشركة مش محتاجة RLS).

## 5. تصميم قاعدة البيانات

### 5.1 أعمدة مشتركة (mixins)
| العمود | الغرض |
|---|---|
| `id UUID` (UUIDv7) | مفتاح أساسي؛ مفيد للأونلاين ومابيكشفش عدد السجلات |
| `company_id UUID` | العزل |
| `version INT` | optimistic locking (SQLAlchemy `version_id_col`) |
| `created_at/by`، `updated_at/by` | التتبع |
| `deleted_at` (للجداول المهمة) | مسح منطقي — ماحدش بيمسح أمر شغل أو حركة مالية فعليًا |

الأرقام المهمة (أطوال، مقاسات، فلوس) `NUMERIC` مش `float`. الأطوال **بالمليمتر** في الداتابيز (`NUMERIC(12,4)`). الإدخال بالسم أو المم والتحويل في الطبقة الخارجية بس. ⚑

### 5.2 المجموعات الأساسية (مختصر)

**التنظيم والأمان**
`companies`، `branches` (نوع: مصنع/مخزن/معرض)، `users`، `roles`، `permissions`، `user_branch_roles`، `refresh_tokens` (hash، الجهاز، انتهاء، revoked)، `devices` (الأجهزة المسجلة + إصدارها، للعدّ في الترخيص)، `audit_log`، `pii_access_log`.

**الترخيص**
`subscriptions` (أونلاين: الموديولات، أقصى فروع، أقصى مستخدمين، تاريخ الانتهاء)، `installed_license` (أوفلاين: نسخة من الملف الموقّع + بصمة الجهاز).

**مكتبة القطاعات + المحرك**
| الجدول | محتواه |
|---|---|
| `suppliers_catalog` | الموردين/الماركات (كومبن، كرافت لاين، نيو لاين…) |
| `profile_systems` | سيستم قطاعات (مورد + سيري + خامة UPVC/شاتر/ألومنيوم)، الحالة: معتمد / تحت التجربة |
| `materials` | كل صنف: كود، اسم، نوع (قطاع/حديد/إكسسوار/زجاج/مستهلكات/أصل)، وحدة، طول العود، وزن، حد أدنى للقطعة، `base_code` + `color_code` |
| `colors` | الألوان ولاحقة الكود |
| `system_constants` | ثوابت السيستم بأسامي (`sash_overlap_total`، `glass_deduction`، `weld_allowance`…) + قيمة + وحدة + وصف |
| `product_templates` | قالب نموذج (جرار 2 ضلفة، مفصلي، قلاب بشفاط، شاتر…) بمتغيراته: W، H، عدد الضلف، أماكن القواطيع، اختيارات (بار، باب/شباك…) |
| `template_formulas` | المعادلات: `output_key` + تعبير بالأسامي + وحدة + ترتيب |
| `template_pieces` | القطع اللي بتتقطع: الدور (حلق/ضلفة/باكتة/حديد…)، معادلة الطول، معادلة العدد، زاوية التقطيع يمين/شمال |

| `template_validations` | قواعد التحقق (رفض/تحذير) |
| `formula_set_versions` | **نسخة مجمّدة** (snapshot JSON + hash) من الثوابت والمعادلات لسيستم معين. أي تعديل = نسخة جديدة |
| `library_packages` | الحزم اللي اتطبقت (الإصدار، التوقيع، الفرق اللي اتعرض، مين وافق) |
| `company_calibrations` | معايرة الشركة لكل سيستم: `(system_id, constant_name, delta)` — مابتعدلش المعادلة الأصلية |
| `company_overrides` | تعديلات الشركة على صنف/ثابت في المكتبة (سعر، كود داخلي، قيمة ثابت) — منفصلة تمامًا عن صفوف المكتبة |

**النواة الإدارية**
`customers` (+ بيانات شخصية معلّمة)، `site_surveys` + `survey_openings` (مقاس الفتحة من المعاينة + خلوص التركيب + مقاس التصنيع المحسوب — الاتنين متسجلين)، `price_lists` (عميل نهائي/تاجر/مقاول) + `price_list_items`، `quotations` + `quotation_lines`، `work_orders` + `work_order_items` + `work_order_stages`، `warehouses`، `stock_items`، `stock_movements` (دفتر حركات، الرصيد = مجموع الحركات)، `stock_transfers`، `suppliers`، `purchase_orders` + `purchase_receipts`، `cashboxes`، `cash_transactions`.

**مخرجات التصنيع** (متخزنة مع أمر الشغل، مش بتتحسب تاني)
`wo_calc_results` (المدخلات + `formula_set_version_id` + المعايرة المستخدمة + المخرجات JSON)، `cut_lists`، `cut_plans` (العيدان والقطع والهالك)، `glass_lists`، `accessory_lists`، `material_costs`، `drawing_data` (JSON).

### 5.3 Optimistic locking
- كل سجل فيه `version`. أي `PUT/PATCH` لازم يبعت `version` اللي قراه (أو هيدر `If-Match`).
- `UPDATE … WHERE id = :id AND version = :v` — لو صفر صفوف اتعدلت: `409 Conflict` ومعاه النسخة الحالية، والواجهة تعرض للمستخدم الفرق.

### 5.4 سجل التعديلات (Audit)
`audit_log`: الجدول، السجل، العملية، القيم القديمة والجديدة (JSONB)، المستخدم، الجهاز، الوقت. بيتكتب من الـ service layer في نفس الـ transaction. الحقول الشخصية بتتسجل كـ "اتغيرت" من غير قيمتها.

## 6. محرك المعادلات (أهم جزء)

### 6.1 مبادئ
- **ولا معادلة ولا ثابت تخصيم في الكود.** الكود فيه بس: الـ parser، والـ evaluator، والقواعد العامة (ترتيب الحساب، التقريب، التحقق).
- كل سيستم قطاعات ليه ثوابته ومعادلاته.
- الحسابات كلها `Decimal`.

### 6.2 لغة المعادلات
تعبيرات بسيطة بأسامي واضحة، مثال (جرار كومبن شباك 3 ضلفة):
```
sash_width       = (opening_width + sash_overlap_total) / leaf_count
sash_height      = opening_height - sash_height_deduction
screen_width     = sash_width + screen_width_extra
glass_width      = sash_width - glass_deduction
```
- المسموح: أرقام، أسماء (متغيرات/ثوابت/مخرجات سابقة)، `+ - * /`، أقواس، مقارنات، `and/or/not`، ودوال من قائمة بيضا: `min max abs round ceil floor if(cond,a,b)` و`step(x, [حد, قيمة]…, else)` لجداول زي مقاس البوكس وقدرة الموتور.
- **Parser مكتوب بإيدينا** (tokenizer + recursive descent → AST). مفيش `eval` ولا `exec` ولا `ast.literal_eval` على نص المستخدم. حدود: طول التعبير، عمق الشجرة، ومفيش وصول لأي attribute أو import.
- قبل الحفظ: تحليل المعادلات، اكتشاف الأسامي المش متعرّفة، وكشف الحلقات (A بتعتمد على B بتعتمد على A)، وترتيب الحساب (topological sort).

### 6.3 الفتحة مقابل التصنيع
```
manufacturing_width  = opening_width  - installation_clearance_width
manufacturing_height = opening_height - installation_clearance_height
```
الاتنين بيتسجلوا في المعاينة وفي أمر الشغل. خلوص التركيب ثابت في السيستم (قابل للمعايرة). ⚑ (الشيت ماذكرهوش.)

### 6.4 المعايرة
`القيمة الفعلية للثابت = قيمة المكتبة (أو override الشركة) + delta معايرة الشركة`. المعادلة نفسها ماتتلمسش. والنتيجة بتتسجل بالمعايرة اللي اتحسبت بيها.

### 6.5 الإصدارات
- أي تعديل في ثوابت/معادلات سيستم = `formula_set_version` جديدة مجمّدة (JSON + SHA-256).
- أمر الشغل بيتسجل بـ `formula_set_version_id` + snapshot المعايرة + المدخلات + المخرجات. **إعادة فتح أمر قديم بتعرض النتايج المتخزنة**، وإعادة الحساب (لو حد طلبها) بتستخدم نفس النسخة القديمة.

### 6.6 التحقق المنطقي
قواعد متخزنة كبيانات ومعاها مستوى (`error` يرفض / `warning` ينبه): قطعة طولها ≤ 0، أقل من الحد الأدنى للقطاع، أطول من العود، الضلفة أكبر من الحلق، الزجاج أكبر من الضلفة/الفتحة، مقاس برّه نطاق الجدول (زي "خارج النطاق" في الشاتر)، عدد بالكسور في حاجة لازم تبقى عدد صحيح.

## 7. مخرجات التصنيع

لكل أمر شغل:
1. **كشف التقطيع**: لكل قطاع: الكود، اللون، الطول (مم)، العدد، الزاوية (45°/90°) يمين وشمال، القطعة دي لأنهي شباك.
2. **تحسين التقطيع** (1D cutting stock): First-Fit-Decreasing + Best-Fit مع تحسين محلي، مع حساب سلاح المنشار (kerf)، وهالك الأطراف، والحد الأدنى للبواقي اللي تترجع المخزن. المخرج: خطة لكل عود + نسبة الهالك. (ممكن نضيف OR-Tools بعدين للأوامر الكبيرة.) ⚑ قيم kerf والأطراف.
3. **كشف الزجاج**: المقاسات، العدد، النوع، المساحة م².
4. **كشف الإكسسوار والخامات**: من معادلات الكميات + البدائل + تبديل اللون.
5. **تكلفة الخامات**: من الأسعار (المكتبة/الشركة/آخر سعر شراء ⚑).
6. **بيانات الرسمة** JSON: الحلق، الضلف، القواطيع، اتجاه الفتح، الأبعاد — الواجهة ترسمها.

## 8. الـ API

- REST + JSON، تحت `/api/v1`. توثيق OpenAPI أوتوماتيك على `/api/docs`.
- مستقل عن نوع العميل (ويب/ديسكتوب/موبايل بعدين): توكن في هيدر `Authorization: Bearer`، مفيش اعتماد على cookies أو session.
- Pagination موحد (`?limit=&cursor=`)، فلترة، ترتيب.
- أخطاء موحدة: `{ "error": { "code": "VERSION_CONFLICT", "message": "...", "details": {...} } }` بكود ثابت والواجهة تترجمه.
- هيدر `X-Client-Version` من كل جهاز. السيرفر بيرد بـ `X-Server-Version` و`X-Min-Client-Version`، ولو الجهاز أقدم من المسموح: `426 Upgrade Required`.
- `GET /api/v1/system/info` (من غير دخول): الإصدار، الوضع، اسم الشركة — بيستخدمه الاكتشاف والأجهزة.
- WebSocket `/api/v1/events`: إشعارات "السجل اتغير" للشركة/الفرع.

مجموعات الـ endpoints: `auth`، `org` (فروع/مستخدمين/أدوار)، `catalog`، `engine` (حساب تجريبي، إدارة المعادلات والمعايرة)، `crm`، `sales`، `manufacturing`، `inventory`، `purchasing`، `treasury`، `privacy`، `system` (license، backups، devices، updates). التفاصيل الكاملة هتبقى في `docs/API.md`.

### الدخول
- `POST /auth/login` ← access token (15 دقيقة) + refresh token (30 يوم، ⚑).
- `POST /auth/refresh`: الـ refresh بيتغير مع كل استخدام؛ لو refresh قديم اتستخدم تاني (احتمال سرقة) كل توكنز الجهاز ده بتتلغي.
- الدخول مربوط بجهاز (`device_id`) عشان عدد الأجهزة في الترخيص.
- قفل مؤقت بعد محاولات فاشلة.

### HTTPS
- أونلاين: إجباري. المقترح Caddy أو Nginx قدام Uvicorn (شهادة Let's Encrypt). Uvicorn كمان يقدر يشغّل TLS بنفسه.
- أوفلاين: اختياري؛ لو اتفعّل بنعمل شهادة self-signed أو CA محلية وقت التسطيب.

## 10. الأوفلاين بالتفصيل

### التسطيب على جهاز السيرفر
PostgreSQL (خدمة ويندوز رسمية) + فولدر البرنامج بالإصدار + خدمة `MYTechServer` (WinSW) بتبدأ أوتوماتيك + قاعدة فايروول للبورت + ملف `.env` بصلاحيات مقفولة. التفاصيل في `docs/INSTALL.md`.

### اكتشاف السيرفر ⚑
- السيرفر بيعلن عن نفسه: **mDNS** (`_mytech._tcp.local`) + بيرد على **UDP broadcast** على بورت ثابت (مثلًا 47800) برسالة فيها الاسم والعنوان والبورت والإصدار وبصمة الشهادة.
- الجهاز يدوّر بالطريقتين، ولو مالقاش يقدر يكتب IP يدوي.
- **القرار:** الواجهة **برنامج ديسكتوب**، فالجهاز بيدوّر على السيرفر بالـ UDP broadcast والـ mDNS، ولو مالقاهوش يكتب الـ IP يدوي. التفاصيل للمطوّر في `docs/API.md` (§ برنامج الديسكتوب).

### الاستمرار والرجوع
- السيرفر مش معتمد على أي جهاز فرعي؛ الجهاز اللي يتقفل ماحدش بيحس بيه.
- الجهاز بيعمل health check دوري و reconnect للـ WebSocket بـ backoff، والتوكن بيتجدد أوتوماتيك. مفيش أي تخزين للعمليات محليًا (مش offline sync).

### الترخيص
ملف JSON موقّع Ed25519 فيه: اسم الشركة، بصمة جهاز السيرفر، الموديولات (`core`، `manufacturing`، `mfg.upvc`، `mfg.shutter`، `mfg.aluminum`)، أقصى عدد أجهزة، تاريخ الإصدار/الانتهاء (اختياري)، رقم الترخيص. المفتاح العام مدمج في البرنامج، والخاص عندك بس في `tools/vendor_admin`.
بصمة الجهاز: hash من Windows `MachineGuid` + السيريال بتاع اللوحة الأم. ⚑ (إيه اللي يحصل لو الجهاز اتغير؟)

## 12. النسخ الاحتياطي

- يوميًا في ميعاد من الإعدادات: `pg_dump -Fc` (+ `pg_dumpall --globals-only`) لفولدر من الإعدادات (`BACKUP_DIR`، ممكن فلاشة أو مسار شبكة)، باسم فيه التاريخ والإصدار و checksum.
- الاحتفاظ بآخر N نسخة (`BACKUP_KEEP`).
- تشفير اختياري للنسخة ⚑.
- أداة `mytech-backup restore <file>`: بتتحقق من الـ checksum، توقف الخدمة، تاخد نسخة من الوضع الحالي الأول، تسترجع، تشغّل الـ migrations لو النسخة أقدم، وتشغّل الخدمة.
- آخر نتيجة نسخ بتظهر في `/system/backups` (والمدير ياخد تنبيه لو فشل).

## 13. التحديثات والإصدارات

- Semantic Versioning + `CHANGELOG.md`.
- **ملف التحديث** (أوفلاين): zip موقّع Ed25519 فيه: `manifest.json` (الإصدار، أقل إصدار ممكن يتحدث منه، أقل إصدار للأجهزة)، البرنامج الجديد، والـ migrations.
- خطوات `updater`:
  1. التحقق من التوقيع والتوافق.
  2. backup كامل (إجباري، لو فشل التحديث يقف).
  3. إيقاف الخدمة.
  4. فك البرنامج الجديد في فولدر جديد بالإصدار (القديم بيفضل زي ما هو).
  5. `alembic upgrade head`.
  6. تشغيل الخدمة على الفولدر الجديد + health check.
  7. لو أي خطوة فشلت: إيقاف، استرجاع الـ backup، الرجوع للفولدر القديم، تشغيل، وتسجيل السبب.
- **قواعد الـ migrations**: ممنوع حذف عمود/جدول فيه بيانات أو تغيير نوعه من غير migration نقل صريح بخطوتين (expand → migrate → contract على إصدارين) + اختبار ليها. كل migration ليه اختبار upgrade على داتابيز فيها بيانات.
- أونلاين: نفس `updater` بيتشغل على السيرفر مرة واحدة.

## 14. حماية البيانات الشخصية (قانون 151 لسنة 2020)

- **تعليم الحقول الشخصية** في الموديلات (`pii=True`): اسم العميل، التليفون، العنوان، الرقم القومي، بيانات الموظفين.
- **سجل الوصول** `pii_access_log`: مين (مستخدم/جهاز/IP)، شاف أو عدّل أو صدّر أو مسح، بيانات مين، أنهي حقول، إمتى. بيتسجل أوتوماتيك من الـ endpoints اللي بترجع حقول شخصية.
- **التصدير**: `GET /privacy/subjects/{id}/export` ← JSON بكل بيانات الشخص.
- **المسح**: `POST /privacy/subjects/{id}/erase` ← **إخفاء الهوية** (anonymization) للحقول الشخصية، مع الإبقاء على السجلات المالية والمحاسبية بدون بيانات تعريفية ⚑ (فيه تعارض محتمل مع الاحتفاظ بالفواتير قانونًا).
- **اللوجات**: فلتر في الـ logging بيحجب الحقول الشخصية والتوكنز والباسوردات، ومفيش body للطلبات في اللوج.
- الباسوردات Argon2id. الأسرار في `.env` بس.
