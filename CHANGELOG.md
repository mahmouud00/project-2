# Changelog

All notable changes are listed here. Versions follow Semantic Versioning (MAJOR.MINOR.PATCH).

## [Unreleased]
### Added
- Profiles in purchase orders are read in bars: the goods order from a work order shows the number of bars and takes the supplier's price per bar, the purchase order page shows quantities and prices per bar (metres beside them), and receiving counts bars. The order still keeps metres and a price per metre underneath, so costs and the company prices are unchanged. `bar_length_mm` on purchase order lines.
- «تحديث بآخر معادلات منشورة» in a work order (before manufacturing): every item is calculated again with its system's current published version and the cut sheet is rebuilt; prices stay as agreed. An order never changes by itself when the formulas are updated, so a model fixed and published after the quotation reaches the order only this way. `POST /work-orders/{id}/recalculate`.
- A work order stage «تركيب» (installation) after «جودة»: reaching it notifies the installations people (notify.field); the technicians page has a tab «التركيبات» listing the orders waiting, where the installations manager gives each to a technician («إسناد لفني»); the installation order appears then (a tab «أمر التركيب» in the work order, the list, and the technician's job) and not before; when the technician finishes the job the order moves to «تسليم» by itself. An order the customer takes himself goes from «جودة» to «تسليم» («تسليم من غير تركيب»). An installation job for an order can only be made once it reached installation (`NOT_READY_FOR_INSTALLATION`). Planned days for the stage in the company data (default 1). `GET /field/installations`.
- «أمر التركيب» (installation order): every window of a work order on its own row — two of the same size are two rows — numbered as on the cut sheet, with where it goes on site, its model, opening and manufacturing sizes with the drawing, colour, glass and options, a box to tick, the customer's address, phone and a QR of the place, and signature lines. Printed or saved as PDF from the work order and from an installation job (the office and the job's own technician). New permission `field.install_doc` («أمر التركيب: يشوفه ويحمّله PDF»), given by migration 0020 to the built-in administrator, installations manager and technician roles. `GET /work-orders/{id}/print/installation`, `GET /field/jobs/{id}/installation-order`.
### Changed
- One window per line: a quotation / invoice / survey line no longer has a count, and its place on site («المكان في الموقع»: floor and room) is required; «شباك زيه في مكان تاني» on a quotation line adds another one with the same specifications. A quotation made from a survey splits an opening with a count into that many lines. Lines saved before with a count keep it (and are listed window by window in the installation order).
- Every window of a work order has its own number (شباك 1، 2، 3… in the order of the lines and their quantities): the items show «شباك 1–2», the cut list says which windows each row is for, and every piece in the bar plan (screen and printed cut sheet) is marked «عرض 2» / «ارتفاع 1», so the cutter writes it on the piece. Work orders whose sheets were built before keep them until they are rebuilt («إعادة الحساب»).
- Purchase orders show the material's name (and colour) next to its code, on the order page and when receiving; the goods order from a work order falls back to the material's name for older orders.
- Formulas and conditions accept a chain of comparisons as written on paper: `60 < ارتفاع_الضلفة <= 90` means `60 < ارتفاع_الضلفة and ارتفاع_الضلفة <= 90` (it was refused). The accessories help shows it.
- «حساب طلبية الشراء», a new model tab (profiles and reinforcement only; accessories are still bought from the accessories tab): rows of material, length to buy and count, written with the model's names (a piece's name is its length, e.g. `عرض_الضلفة + 4`), with a condition, «سطر لكل قطعة» to start from the pieces and «نسخ من نموذج تاني». The cut list keeps coming from the pieces; what the work order asks to buy (material needs, the goods order to the supplier) comes from these rows, packed into whole bars (only the bar ends trimmed, the rows already hold the cut). A material without rows is bought from its pieces as before; orders made before keep their figures. Checked before publishing, shown in «تجربة الحساب». `Definition.purchase`, `purchase` in the calculation and the work order outputs.
- Model editor: the material of a piece, glass or accessory is chosen from a list with a search box (type part of the code or the name; ↑ ↓ Enter), and the variables, glass, accessories and rules tabs have «نسخ من نموذج تاني»: choose a system and a model, tick its rows, and they are added (a row with the same name replaces this model's one).
- A model's code can be changed in the model editor («الكود»), unique in its system. Published versions keep the old code; a calculation with them finds the model by its id, so quotations and orders made before are not affected.
- Copy models to another system (library ← system ← models ← «نسخ لقطاع تاني»): choose models, choose a system of your own with the same unit, see what will happen, copy. A model the other system lacks is copied whole (data, pictures, colour pictures, variables, formulas, pieces with their deductions, glass, accessories, rules, drawing, reference tests) as a trial; a model it already has (same name, loosely spelled, or same code) keeps everything of its own and only gets what it lacks (missing keys, colour pictures, the picture / description / drawing when empty, the tests when it had no pieces). Constants the formulas need that the other system lacks are listed, and copied with their values only when asked. `POST /library/systems/{id}/models/copy?apply=`.
- «ابدأ الشغل على البرنامج» on the dashboard of a new factory (for who manages the company): company data and logo → systems → material prices → users → the first quotation, each ticked from the company's own data, with a progress bar and a button to the right page; «إخفاء» closes it, and it goes once everything is done. `GET /company/setup`, `POST /company/setup/dismiss`.
- Every build has its own version, `<major>.<minor>.<build number>` (e.g. 0.1.57), stamped by the workflow into the server, the desktop program and the Android app, so programs can tell which one is newer. Releases are tagged `v0.1.57`.
- The desktop program and the phone app update from the factory server: every server build carries the desktop installer and the APK of the same build (`app\<version>\clients\`, in the installer and in the `.mtu`), and an older program shows «فيه نسخة جديدة» (also on the login screen) with «تحديث», which downloads it from the server — no internet, no links to send. `GET /system/clients` (public) and `GET /system/clients/{desktop|android}`; setting `CLIENTS_DIR` to use another folder (online).
- Updating the server from the program: «الترخيص والنسخ ← تحديث السيرفر» takes the signed `.mtu`, checks its signature and that it is newer, and starts `scripts\update.ps1` as a Windows scheduled task (`MYTech Update`, outside the service) — the same backup / migrate / health check / automatic rollback as before. `GET|POST /system/update` (system.manage; online: MYTech only).
- An encrypted copy of every backup outside the factory: «النسخ الاحتياطي ← نسخة متشفّرة برّه المصنع» takes a folder on the server PC (a Google Drive / OneDrive folder, which their program uploads, or a USB / network drive) and a password; each backup and the new pictures are written there with AES-256-GCM (key from scrypt). The password is kept encrypted (from JWT_SECRET). `mytech-server decrypt-backup` turns a copy back into a `.dump`. `GET|PUT /system/backups/offsite`.
- When backups stop (none for a day and a half) or the outside copy fails, everyone with system.manage is notified every morning, and the backup page says so.
- Two-step login with an authenticator app (Google / Microsoft Authenticator): user menu ← «الأمان والأجهزة» ← scan the QR and confirm a code; from then on signing in asks for the 6-digit code after the password (a wrong code counts towards the lock, a code works once). Company data ← «إلزام المديرين بالتأكيد بخطوتين» makes administrators set it up when they sign in and stops them turning it off. A lost phone: «إلغاؤه» on the users page, or `mytech-server reset-2fa --username …` on the server. The secret is stored encrypted (from JWT_SECRET) and never logged. Migration 0019 (three nullable columns on users).
- «الأجهزة اللي داخل منها»: every device the user is signed in on, with «طلّعه». Signing in again on a device ends its earlier sign-in, so the list stays one row per device.
- Send a quotation or an issued invoice to the customer on WhatsApp («واتساب»: a chat with the customer's number and a ready message) or copy the message («نسخ اللينك»). The message carries a link the customer opens without an account, on the phone too: the document as printed, and for a quotation «موافق على العرض» or a change request with a note. The quotation shows what happened (sent and not opened, opened, approved, change asked with the note); the sales people and whoever sent it are notified. Sharing a draft quotation sends it, with the same checks; approving goes through them again. Links last 14 days, an older message's link keeps working, «إلغاء اللينكات» stops them all; only the token's hash is stored; link previews (WhatsApp) are not counted as the customer. Migration 0018 (`document_shares`, RLS). New setting `PUBLIC_URL` (the address customers open links on; without it a factory server's link only opens inside the factory).
- The window drawing shows its measurements: on the quotation and invoice printouts every line's drawing has its width above and height beside it in cm (the opening the customer ordered), the cut list's drawings their manufacturing size; on screen the line form and the model editor's calculation show them in the company unit. The printout drawings are a little larger to fit them.
### Fixed
- A plain tilt window was also drawn like a tilt-turn one on the printouts.
- Change history on every record page (the clock in the top bar): who added, changed or deleted what and when, field by field (old ← new), with the record's lines (a quotation's prices are on its lines). Quotations, work orders, surveys, invoices, purchase orders, customers, employees, library systems and models. `GET /history/{kind}/{id}`: anyone who may read the record (in their company and branches) may read its history; personal data stays masked as it was logged.
- Unsaved work is not lost: the survey sheet, the model editor and the quotation line form keep what is typed on that computer until it is saved; reopening the screen offers «رجّع التعديلات» / «تجاهلها». The draft is only offered when the record has not been saved since (so it never overwrites anyone's changes), is forgotten once saved, and is dropped after 30 days. Nothing is sent anywhere by itself (not an offline sync).
- Every table (with more than a few rows) has tools: a quick filter over the rows on screen (with a count), the columns to show (remembered per table on that computer), and Excel / PDF of exactly what is shown (filtered rows, chosen columns, shown order). Any titled column sorts when its header is clicked (by what the cell shows; numbers as numbers), click again for the other way, a third time to undo. The page print skips filtered-out rows. New `POST /documents/report.xlsx` (same body as the report printout; numbers in numeric columns become numbers, every other cell stays text and never a formula).
- Search everything (Ctrl + K, or the magnifier in the top bar): customers (name, code, phone), surveys, quotations, work orders and invoices (number or customer name), purchase orders and suppliers, employees, and library systems, models and materials (code or name), grouped, opened with the keyboard (↑ ↓ Enter). `GET /search?q=` searches only the sections and branches the user may read, in their company; the customer, employee and supplier data it shows is logged in the personal-data access log.
- Back and forward arrows in the top bar (also Alt + ← / →, the mouse's back / forward buttons and the phone's back button): every page is a numbered history entry, tabs and filters change the page in place, and the arrows are greyed out when there is nowhere to go. Leaving the survey sheet or the model editor with unsaved changes asks first («اخرج من غير حفظ» / «رجوع»), whatever way you leave.
- Where the page is, above its title, with each part clickable: «مكتبة القطاعات › كومبن › النماذج» on a model, the section on every record page.
- Window/door models from Excel (library ← استيراد من إكسيل ← «استيراد النماذج من إكسيل», `POST /library/models/import?apply=&system_ids=`): a list with الكود / الاسم (or الرقم المرجعي / اسم المنتج), optionally النوع (شباك / باب) and الرسمة (drawing JSON), created in every chosen system of the company's own (all UPVC ones by default) with their name, type and drawing only — pieces and formulas (the deductions) are entered in the model editor. Preview first, all or nothing; a code already in a system is skipped there.
- Deleting several models at once (models tab ← «حذف أكتر من نموذج»): pick models or all of them; each one waits 30 days, or is erased at once when the permanent delete permission chooses to.
### Fixed
- A plain tilt window (bottom-hung) was drawn like a tilt-turn one; it shows the tilt triangle only.
- A model's main picture can be removed (not only replaced), and its type is chosen from a list (شباك / باب / شيش) instead of typed, so imported models no longer show «window».
- Everything in centimetres: new profile systems (API default, Excel import) are written in cm; the Excel template's bar length is in cm («طول العود (سم)», files with «طول العود (مم)» are still read). Migration 0017 switches every existing mm system that has no model and no published version to cm with the same lengths (its constants and companies' calibration deltas / overrides ÷ 10); a system with models keeps mm. Changing a system's unit now converts its constants (0.5 mm → 0.05 cm) instead of reinterpreting them, and is refused for a system with models or versions (`UNIT_LOCKED`), whose formulas may hold plain numbers that cannot be converted safely.
- A work order that cannot be deleted now says why (`WO_IN_USE` details: its invoices — a draft one made by the «فاتورة» button counts — with number, status and pending deletion, and any money received) and the way out of each; it only suggests cancelling when the order can still be cancelled (not once delivered).
- A quotation that cannot be deleted now says which work order or invoice keeps it (`QUOTE_IN_USE` details: kind, number, and whether its own deletion is already counting down) and what to do; the delete confirmation closes on a refusal instead of staying open (clicking again only repeated the same error).
- MYTech can copy a company's own profile systems into the library (library ← update packages ← «نسخ سيستمات شركة للمكتبة», `GET /library/copy/sources`, `POST /library/copy/run`): the chosen systems — with their constants, materials (colour variants included), models (images included) and reference test cases — are copied as fresh, unpublished library rows under the platform company; the company's own rows are untouched, a code already in the library is skipped, and a material already in the library (by code) is reused. For when systems were entered under the company account instead of the MYTech developer account. Platform author only; reads the company's rows through the system (BYPASSRLS) session, as package import does.
- Login screen is now an interactive UPVC window: two closed glass sashes that slide open on a click to reveal the username/password/server fields (works online, offline and for the MYTech developer account; light and dark).
- A «مساعدة» (?) button on every page's top bar opens a short, accurate explanation of that screen; the long library/model-editor explanations now live inside per-section «مساعدة» buttons instead of always-visible paragraphs.
### Changed
- The remaining length fields that were fixed to millimetres (system rounding step, material bar length and min piece, machine saw kerf/bar trim/min reusable offcut, model-editor reference-test and glass values, offcut length) now use the company's display unit (centimetres by default); values are still stored in millimetres internally and the 0.1 mm publishing tolerance is unchanged.
- Login on a factory (offline) server: «دخول MYTech (للمطوّر)» logs into MYTech's own account (library authoring and update packages); the screen otherwise logs into the server's one company and had no way to reach it. LIBRARY.md says how to create that account on an installed Windows server.
- Deletion after 30 days (migration 0016): every delete button asks for the deletion; the record stays usable with a «جاري الحذف» countdown and is erased when its 30 days are up (scheduler, hourly). The new permission `delete.permanent` (the built-in administrator has it; the administrator gives it to whom they choose) erases at once from the countdown; the one who asked or that holder can take it back (`/deletions`, `/deletions/{id}/now`, `/deletions/{id}/cancel`, the «جاري الحذف» page). The same rules as before are checked when asked (an issued invoice still cannot be deleted); money movements are still reversed, never deleted. Holders of the permission are notified of each request.
- A library system, material or model that old work points to is now hidden from every list when deleted (instead of only stopped), and its code can be used again; a material used by models can be deleted. Open work that uses it (an open survey, a quotation not accepted, an order not in manufacturing, a purchase not ordered, a library model) is told to replace it: its maker and the section's managers get a notification when the deletion is asked for and when it is done, and its lines are marked «النموذج اتحذف من المكتبة: غيّره». Closed work keeps its copy.
- Deleting an employee with salaries or sales hides them as well (marked as left); their history keeps their name.
- Sales guide instead of price lists (migration 0015): each line and each survey shows the company's cost of the job (materials after the supplier discount + waste + labour per m²) with two prices on it, the fair price (cost + 20 %) and the top price (cost + 30 %); margins and labour per m² are company settings. The salesperson types the price; a line without one stays unpriced and the quotation cannot be sent or accepted. A total after the discount under the fair total needs the sales manager's approval (`quotes.approve_price`, `POST /quotations/{id}/request-price-approval` and `/approve-price`); lowering it again needs another approval.
### Changed
- Offcuts are called «الفُضل», one offcut «فضلة» (was «البواقي» / «باقي») on every screen, the cut list and the docs.
### Removed
- Price lists (`/price-lists`, the «قوائم الأسعار» page, the customer's price list and the `pricelists.*` permissions). The tables stay for old quotations, whose line prices are kept even when recalculated.
- Formulas: a piece's name can be used in another piece's (or glass, accessory, check, drawing) expression and means that piece's length formula, exactly as if written in place (system unit, before rounding); pieces depending on each other in a circle are refused; the model editor lists piece names among the names available.
- Company prices are shown: materials carry `company_prices` (the current company's price, discount and price after discount per colour); the library list has a «سعر شركتك» column and the material screen shows and edits the price per colour.
### Fixed
- Model editor: the check's error messages were shown as empty red bars (the server sends plain text); they are shown again.
### Added
- Materials import from Excel (`POST /library/import-excel?apply=`, template `GET /library/import-excel/template`, "استيراد من إكسيل" tab in the library): colours, profile systems and materials in their colours with the supplier price, preview first and then all or nothing; existing codes are updated, nothing is deleted. MYTech imports into the shared library (reference prices); a company imports its own materials and its prices for library materials without changing them. Prices per bar and per kg (with a weight per metre) become prices per metre.
- Supplier discount (migration 0014): per material and colour (`discount_pct` in the company's material settings and the Excel column «خصم المورد %») or per profile system (company setting `supplier_discounts`); costs use the price after the discount.
- Offcuts (البواقي, migration 0013): every leftover of at least "أقل باقي يتشال" (400 mm unless the company set another value) is kept per profile and colour with its exact length when an order starts manufacturing; later orders cut from the offcuts in stock first (cutting optimiser `stock`), so fewer new bars are needed and bought; used offcuts are marked with the order; leftovers counted by hand can be added and any can be scrapped (`/offcuts`). Cut lists mark offcut bars with ♻.
- Sales confirmed by the accounts (migration 0012): a work order made from an accepted quotation waits for `POST /work-orders/{id}/approve-sale` (`sales.approve`) before it can be approved and made; "تأكيد المبيعات" tab in the accounts page. Orders already past the quotation stage count as confirmed.
- Notifications (`/notifications`): the bell in the program and a Windows / Android notification for each new one (Tauri notification plugin; the program asks the server every 15 s, on the factory network). Accounts: sales and purchases to confirm; sales: any change on customers, surveys, quotations, confirmations, payments, invoices, maintenance; production: confirmed sales and every work order stage; installations: technicians' jobs and their progress, maintenance requests; a technician is told about his own new job. Who gets them is a permission per section (`notify.accounts/sales/production/field`); new built-in roles "مدير مبيعات", "مدير تصنيع", "مدير تركيبات". Kept 90 days.
- HR (الموارد البشرية): employees with their job, department, branch, salary and leave balance, optionally linked to their user; bonuses and deductions on a month's salary; advances paid from a cashbox and taken back in monthly instalments; leave (annual, sick, unpaid deducted at salary ÷ 30 per day); monthly payroll per branch, paid from a cashbox with one payment per employee and closed after payment. Personal data reads are logged. New permissions `hr.read/create/write/delete/payroll` and a built-in "HR" role.
- The salesperson of every sale (`salesperson_id` on quotations, carried to the work order and the invoice; by default the employee linked to the user who sells) and each employee's sales in their profile.
- Purchase approval by the accounts: a new purchase order waits for `POST /purchase-orders/{id}/approve` (`purchasing.approve`) before it can be ordered from the supplier; "تأكيد المشتريات" tab in the accounts page.
- Company assets (no depreciation) and capital in the company settings; company profit month by month (sales − purchases received − salaries − expenses) and capital = opening capital + assets + accumulated profit (`/finance/profit`, `/finance/capital`, `finance.read`).
### Removed
- The warehouse module (warehouses, stock balances and movements, transfers) at the owner's request: goods are bought per order. Migration 0011 drops those tables with their data and the warehouse links of purchase and work orders; nothing else changes. `inventory.*` permissions and the unused built-in "warehouses" role are removed.
- Server installer: "mytech-service.exe Access is denied" on upgrade: while files are replaced the service's automatic restart is off (restored by setup), running programs are found through WMI (paths of service processes were sometimes unreadable), nothing may still run from the install folder before copying, and a still-locked service file is replaced at the next restart instead of stopping the installation.
- The same program on Android phones (`MYTech-Mobile-<v>.apk`, built by CI from the desktop code with Tauri): phone layout (side menu as a drawer, one-column forms, full-screen dialogs); technicians open on "مهامي" with the job cards, call / map buttons and the phone's own GPS (works with the factory's http server); map links and calls open through the opener plugin (map hosts and `tel:` only). Signed with the `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASSWORD` secrets (alias `mytech`), or a temporary key until they are set.
- Moving to another server: `export --out file.zip` (database + pictures) and `import file.zip`; every backup also copies new pictures to `<backup dir>/media` (pictures were not in backups before). Steps in `docs/MOVE.md`.
- Field service (migration 0010): survey location as a Google Maps link (coordinates read from the link; QR code on the printed survey); maintenance requests per customer (`/maintenance`); technician jobs for surveys, installations and maintenance (`/field/jobs`) with on the way / arrived / done; GPS points from the technician's phone accepted only during a job, every read logged as personal-data access, erased after `LOCATION_RETENTION_DAYS`; the technicians' phone app served by the server at `/tech` (installable, same API as the desktop); new permissions `maintenance.*`, `field.read/manage/delete/self` and a built-in "technician" role.
- Work order progress: planned days per stage (`stage_durations_days` setting) give `progress_pct`, `expected_delivery` and `late` on every work order.
- Goods order from a work order: `GET /work-orders/{id}/material-needs` (whole bars after cutting optimisation, glass by type, each model's accessories, stock on hand) and purchase orders linked to the work order and its customer (`work_order_id`, `customer_id`).
- Capacity for 20-40 users on one server: database pool and request threads configurable (`DB_POOL_SIZE`, `DB_MAX_OVERFLOW`, `REQUEST_THREADS`); the server installer tunes PostgreSQL to the PC's memory.
- Server installer: the firewall rules for the MYTech port (TCP 8000) and discovery (UDP 47800) apply to every network profile, so other PCs reach the server even when Windows marks the factory Wi-Fi as "Public"; upgrades widen the old Private/Domain rules.
- Print any screen: a print button on every page of the desktop app sends what the page shows (its tables, details and totals) to `POST /documents/report`, which returns an A4 document with the company's logo and details to print or save as PDF. Allowed in read-only licence mode.
- Desktop: delete buttons (with confirmation) on customers, surveys, quotations, price lists, work orders, invoices (drafts; issued ones are cancelled), warehouses, transfers, suppliers, purchase orders, cashboxes and the library (systems, materials, models); add and delete buttons only show for users with that permission; the role editor groups permissions by section with delete in red.
- Separate add and delete permissions per section (`X.create`, `X.delete`; migration 0009 gives "add" to whoever could edit, "delete" to the built-in administrator only) and delete endpoints for customers, surveys, quotations, price lists, work orders, invoices, warehouses, transfers, suppliers, purchase orders, cashboxes and the library (systems, materials, models). Records with history are kept: anything already used is deactivated (`{"result": "deactivated"}`) or refused with a reason (`QUOTE_IN_USE`, `WO_IN_USE`, `INVOICE_ISSUED`, `PO_NOT_DRAFT`, `TRANSFER_SENT`, `MATERIAL_IN_USE`); money is corrected by reversing a transaction (`treasury.delete`) and an issued invoice is cancelled (`invoices.delete`).
- Model editor: the drawing (sketch) tab is hidden for models without a sketch; documents show the uploaded pictures.
- Arabic everywhere for factory users: engine and definition-check messages in Arabic (codes unchanged), every API error code has an Arabic message in the desktop app, built-in names shown as العرض / الارتفاع / عرض_الفتحة / ارتفاع_الفتحة / خلوص_العرض / خلوص_الارتفاع, constant and element names in Arabic (no English field left in the model editor), drawing types and openings in Arabic, a piece's role follows its Arabic element name. The demo library is written in Arabic and without helper values; the helper-values section only shows for models that already have them.
- Model editor: "copy the deductions of another model" (same system): pieces with their helper values and parameters, optionally glass, accessories, validations and drawing. Helper values (formulas) are now an optional section of the pieces tab instead of a tab of their own. Arabic inside code/formula text is shown joined.
- A picture of each model per colour (`color_images`, migration 0008): quotations, invoices, work orders and printed documents show the picture of the line's colour, else the main picture; exported in library packages. Model editor: "صورة لكل لون".
- Formulas in Arabic: Arabic digits, `٫` `،` `×` `÷`, the words و / أو / مش / صح / خطأ, Arabic function names (لو، أصغر، أكبر، تقريب، جدول، طول_القوس، ...) and built-in names (العرض، الارتفاع، عرض_الفتحة، ...). Each maps to the English form, so results are identical; names you define could already be Arabic. The model editor shows formulas right-to-left when they are Arabic.
- Half-circle arch (أرج) above a unit: when the total height is above the opening height, the arch is a separate fixed unit with its own frame, calculated with its library model (per unit or the company's `default_arch_model_id`) at width × (total − height). Its cost is part of the unit, it is a linked quotation line (`parent_line_id`, price inside the unit) and a work order item of its own (migration 0007).
- Formula language: geometry functions in exact decimals (`pi`, `sqrt`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `rad`, `deg`, `arc_length`, `segment_area`, `arc_radius`, `arc_angle`); glass panes can give their real area (`area_expr`) for shaped glass. Demo library: example arch model `AR1`.

### Changed
- Server installer: PostgreSQL binaries are installed once (an upgrade never rewrites them); stop-services also ends a PostgreSQL left running without its service; the uninstaller stops everything before removing the services (it could leave postgres.exe running with its files locked). CI uninstalls with both services running and checks nothing is left.
- `GET /surveys` returns each survey's openings (the list showed 0 units).
- Server installer: stops the MYTech and PostgreSQL services before replacing files (upgrade over a running install failed with "Access is denied"), with `stop-services.ps1`: waits up to 2 minutes, falls back to `pg_ctl stop` and to ending leftover processes, logs to `logs\install.log`; tested in CI on running services.
- Licence files saved with a UTF-8 BOM (e.g. by Notepad) are accepted.
- Windows: the server exe is a console program (setup scripts wait for it); stopping the service also stops the server process (job object); the server installer turns off Inno RedirectionGuard (error 448).
- The vendor public key is a compiled-in constant (`app/licensing/vendor_key.py`) instead of a `.pem` file next to the program; a real key pair replaced the development key; private keys are stored encrypted.
